# 图表 (Chart) 解析与渲染开发计划

## 1. 项目背景与目标

本计划旨在为 Office 解析渲染器提供通用的图表支持。图表是 Office 文档（Word, PPT, Excel）中至关重要的可视化组件。
目标是实现一套**独立、通用、可扩展**的图表解析与渲染引擎，能够兼容 `docx`、`pptx` 和 `xlsx` 等多种格式，并支持从 XML 解析到 Canvas/SVG 渲染的全流程。

## 2. 核心架构设计

### 2.1 模块定位
建议将图表核心逻辑置于公共包中，以最大化复用性：
- **位置**: `packages/shared/src/chart`
- **职能**: 负责定义图表通用数据模型、XML 解析策略以及渲染器接口。

### 2.2 数据流向
1.  **Input**: Office Open XML (OOXML) 原始数据 (如 `chart.xml`, `style.xml`, `colors.xml`)。
2.  **Parser**: 解析 XML，提取核心数据（分类、系列、数值、样式），转换为中间格式 (IR)。
3.  **Model**: `ChartModel`，一个清洗过的、扁平化的、对渲染友好的 JSON 对象。
4.  **Renderer**: 消费 `ChartModel`，使用 Canvas 或 SVG 绘制最终图形。

### 2.3 目录结构规划
```text
packages/shared/src/chart/
├── model/                # 数据模型定义
│   ├── IChartData.ts     # 核心接口
│   ├── Enums.ts          # 图表类型、轴位置等枚举
│   └── ...
├── parser/               # 解析层
│   ├── ChartParser.ts    # 解析入口
│   ├── strategies/       # 各类型图表的具体解析策略
│   │   ├── BarChartStrategy.ts
│   │   ├── LineChartStrategy.ts
│   │   └── ...
│   └── utils/            # XML 辅助解析工具
├── renderer/             # 渲染层
│   ├── ChartRenderer.ts  # 渲染入口
│   ├── canvas/           # Canvas 实现
│   │   ├── components/   # 轴、图例、网格线等组件绘制
│   │   └── shapes/       # 柱、线、点等图元绘制
│   └── ...
└── index.ts              # 模块导出
```

## 3. 功能特性矩阵

### 3.1 图表类型支持 (按优先级)
| 阶段 | 图表类型 | 细分变体 | 说明 |
| :--- | :--- | :--- | :--- |
| **P0** | **柱状图 (Bar/Column)** | 簇状 (Clustered) | 最基础，优先实现 |
| | | 堆积 (Stacked) | |
| | | 百分比堆积 (100% Stacked) | |
| **P1** | **折线图 (Line)** | 基础折线 | |
| | | 数据点折线 (Markers) | |
| | | 堆积折线 | |
| **P1** | **饼图 (Pie)** | 基础饼图 | |
| | | 环形图 (Doughnut) | 结构相似，一并处理 |
| **P2** | **散点图 (Scatter)** | 基础散点 | 需要处理 XY 均为数值的情况 |
| | **组合图 (Combination)** | 柱 + 线 | 需要支持双 Y 轴 |
| **P3** | **雷达图 (Radar)** | | |

### 3.2 渲染特性
- [ ] **坐标轴 (Axes)**: 包含主/次坐标轴、网格线、刻度标签、标题。
- [ ] **图例 (Legend)**: 支持上下左右布局。
- [ ] **数据标签 (Data Labels)**: 在图表元素上显示数值。
- [ ] **数据表 (Data Table)**: 图表下方的数据表格。
- [ ] **样式 (Style)**: 填充色、边框、字体、阴影效果。

## 4. 开发路标 (Roadmap)

### 第一阶段：基础架构与 MVP (预计 1-2 周)
- **目标**: 能够解析并渲染一个简单的簇状柱状图。
- **任务**:
    1. 搭建 `packages/shared/src/chart` 目录。
    2. 定义 `IChartData` 接口。
    3. 实现 `ChartParser` 读取 `c:barChart` 节点。
    4. 实现 `CanvasChartRenderer` 绘制 X/Y 轴和矩形条。
    5. 集成到现有渲染流程中进行测试。

### 第二阶段：核心图表扩展 (预计 2-3 周)
- **目标**: 完成 P0 和 P1 级图表类型的支持。
- **任务**:
    1. 抽象坐标轴计算逻辑（线性比例尺、分类比例尺）。
    2. 实现折线图渲染器（贝塞尔曲线平滑处理）。
    3. 实现饼图渲染器（扇形几何计算）。
    4. 完善图例和标题的布局计算。

### 第三阶段：复杂特性与优化 (预计 长期)
- **目标**: 支持组合图表、复杂样式及性能优化。
- **任务**:
    1. 支持多轴系统（主次坐标轴）。
    2. 实现堆积逻辑的通用处理。
    3. 优化渲染性能（大数量级数据点）。
    4. 错误处理与降级策略（遇到不支持的图表类型时显示占位或提示）。

## 5. 技术难点与应对

- **XML 结构复杂**: OOXML 图表定义非常繁琐，嵌套极深。
    - *对策*: 编写专门的 XML Helper 工具类，使用 XPath 或选择器模式简化提取。
- **坐标系转换**: 不同的图表类型有不同的坐标逻辑（笛卡尔坐标 vs 极坐标）。
    - *对策*: 抽象 `CoordinateSystem` 接口，隔离具体计算细节。
- **文本排版**: Canvas 文本换行和对齐处理较麻烦。
    - *对策*: 复用现有的文本测量和布局工具（如果有），或实现简易的 Text Box 模型。

## 6. 测试策略
- **单元测试**: 针对 Parser 编写测试用例，输入 XML 片段，断言 JSON 输出。
- **快照测试**: 对比渲染输出的 Canvas 图像与基准图像（Visual Regression Testing）。
- **真机/集成测试**: 导入实际的 docx/pptx 文件，人工验收渲染效果。
